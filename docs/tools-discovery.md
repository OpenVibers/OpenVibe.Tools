# Gateway discovery

`GET /api/v1/tools/popular?limit=12` ranks successful API uses in the last 168 UTC hour buckets. `GET /api/v1/tools/trending?window=hour&limit=12` ranks positive absolute increases versus the preceding hour; `window=week` (default) compares the last 168 buckets with the preceding 168. The current hour is partial. Ties use current uses, then tool ID. Limits are 1–50.

The response is `{ metric: "successful_api_runs", window, updated_at, uses_today, tools, count }`. Each tool includes its ID, name, keyword-rich description, family, icon, canonical URL and uses. Trending includes previous_uses and increase. Uses today starts at midnight UTC. Public CORS, one-minute caching, 400 for invalid parameters, 503/no-store when the database cannot answer. Empty arrays mean zero observed usage, not an error.

Migration 0012 adds tool_usage_hourly. Gateway inline success records once after replay handling; successful tool jobs record in their completion transaction. Cache hits count, idempotent replays and failed/cancelled runs do not. No inputs, addresses or actor identities are stored. Browser-only transforms, legacy endpoints and jobs without a tool ID are outside this metric. No backfill is invented; totals accumulate after rollout. Rollups survive job expiry. Counts currently retain indefinitely at one row per active tool-hour.

The server renders every category's tools and ItemList JSON-LD. The top strip uses real rankings then catalog choices to fill twelve slots; with no usage it says Explore tools. Kit rows, buttons and drifting strips use the existing Shared component implementations documented in OpenVibe.Design. Headline rotation pauses with its control, while hidden, and for reduced motion. Catalog task matching at /ask-tool redirects one match to its tool or multiple matches to server-rendered search; it does not call a paid AI service.

Launch dates in registry/discovery.js are authored from Tools PR #98, not first-seen telemetry. Add future catalog launches there. The SDK companion PR adds ov.tools.trending() and ov.tools.popular(); it can ship after the gateway API. No production migration or deployment is performed by this PR.

Validation: `ov test --script test:discovery` runs the discovery, home, existing opens, run API, job usage and performance regressions (the script is `node test/run.js` with those files; the pipeline's verify runs the whole suite afterwards). The home measured 209 KB HTML (27.3 KB Brotli) with all 184 tool links and the category ItemLists, and the JavaScript budget covers the shared kit behavior. HTML allows space for fully populated ranking rows.
